Subnet Planner

Subnet Planner

📐 工作原理與說明
子網劃分計算
指定新字首：子網數 = 2^(新字首 − 原字首)
指定數量：需借主機位 n = ⌈log₂(子網數)⌉
新字首 = 原字首 + n；實際子網數 = 2^n（向上取整到 2 的冪）
每子網地址數 = 2^(32 − 新字首)
可用主機 = 地址數 − 2（/31 為 2，/32 為 1）
網路地址 = 原IP 與原掩碼按位與
子網 i 網路地址 = 基網路 + i × 子網大小
可用範圍 = 網路地址+1 ~ 廣播地址−1
約束：新字首 > 原字首且 ≤32

Key formulas: (netAddr+subnetSize-1)>>>0; min(subCount,1024); (2)^newMask-oldMask

📋 劃分規則

等長子網劃分：每借用 n 位主機位，可將原網路劃分為 2ⁿ 個子網。
新字首 = 原字首 + n，每個子網容量 = 2^(32−新字首)。
可用主機數：新字首 ≥31 時為點對點/單機；否則為 2^(32−新字首) − 2（去除網路號與廣播）。
子網序號 i 的網路地址 = 基址 + i × 子網容量。

📚 深度解析：子網劃分與地址規劃

💡 常見使用場景

  • 把一個大網段按新字首等長劃分，得到各子網地址、可用範圍與廣播地址。
  • 按需要的子網數量反推應借幾位，避免劃分後主機數不夠。
  • 給各部門或樓層分配子網時預生成清單，直接寫進配置文件。
192.168.1.0/24 劃分為 /26
新字首 /26 → 子網數 = 2^(26−24) = 4 個；每子網地址數 = 2^(32−26) = 64，可用主機 = 64 − 2 = 62 臺。新子網掩碼 255.255.255.192，四個子網分別是 192.168.1.0/26、192.168.1.64/26、192.168.1.128/26、192.168.1.192/26，各自可用範圍為 .1–.62、.65–.126、.129–.190、.193–.254。若按"需要 6 個子網"劃分，工具會向上取到 3 位借位 → /27，得 8 個子網、每子網 30 臺可用主機。

❓ 常見問題（FAQ）

為什麼每子網的可用主機要減 2？
每個子網的網路地址（全 0）與廣播地址（全 1）不能分配給主機，因此可用數 = 地址數 − 2。/31 與 /32 是例外，按點對點鏈路與主機路由處理。
按子網數量劃分時為什麼數量會變多？
子網數必須是 2 的整數次冪。若你要 6 個，工具會向上取到 8 個（借 3 位），多出的 2 個子網可留作備用或後續合併。
