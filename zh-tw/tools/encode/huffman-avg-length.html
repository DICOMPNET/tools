🔐 Huffman Average Code Length

Estimate the average code length and compression efficiency from symbol frequencies per Huffman coding.

📐 計算公式與說明

哈夫曼平均碼長（本頁程式碼口徑，固定三符號）：平均碼長 L̄=(f₁×l₁+f₂×l₂+f₃×l₃)÷(f₁+f₂+f₃)（bit/符號，fᵢ 符號頻率、lᵢ 對應碼長，保留 4 位小數）；聯動量：總頻數=f₁+f₂+f₃。校驗：六項輸入空值/非法值即提示並中止。判據：無固定分級，加權平均碼長以資訊熵 H 為理論下界，越接近 H 壓縮效率越高（頁面文案口徑，程式碼不計算 H）。

輸入頻率（或機率，歸一化後結果一致）。

💡 常見使用場景

  • 壓縮方案評估：對比哈夫曼與定長/算術編碼的平均碼長。
  • 教學演示：展示高頻符號配短碼、低頻配長碼的最優字首樹。
  • 格式最佳化：為日誌/協議選擇符號機率模型以縮短平均長度。
示例：A:0.5 B:0.25 C:0.25
哈夫曼碼 A=0,B=10,C=11，平均碼長=0.5×1+0.25×2+0.25×2=1.5 bit/符號（熵=1.5，已達最優）。

❓ 常見問題（FAQ）

哈夫曼為何最優？
在滿足字首碼條件下使平均碼長最小，等於資訊熵（機率取 2 的冪時）。
與算術編碼區別？
算術編碼可超越符號邊界、更接近熵，哈夫曼實現簡單但略有冗餘。
頻率未知怎麼辦？
需先統計或使用通用模型，動態場景可用自適應哈夫曼。
