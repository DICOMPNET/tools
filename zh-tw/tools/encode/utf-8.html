💾 UTF-8 Byte Count

Estimate the UTF-8 byte size from counts of ASCII and multibyte characters (CJK, emoji) for storage estimation.

📐 計算公式與說明

ASCII = 1 位元組
拉丁/希臘等 = 2 位元組
CJK 常用字 = 3 位元組
Emoji = 4 位元組

用於估算多語言文本儲存空間。

📚 深度解析：UTF-8 位元組數

💡 常見使用場景

  • 儲存規劃：混合中英文文本按字元型別估算位元組體積。
  • 傳輸預算：介面報文 UTF-8 編碼後的真實位元組長度。
  • 資料庫欄位：為 VARCHAR 按位元組而非字元設寬度（如 MySQL utf8mb4）。
示例：10 ASCII + 5 中文
10×1 + 5×3 = 25 位元組；若含 emoji 則為 4 位元組/個。

❓ 常見問題（FAQ）

UTF-8 為何變長？
ASCII 1 位元組、常用漢字 3 位元組、部分符號/emoji 4 位元組，兼顧相容與節省。
emoji 佔幾字節？
多為 4 位元組（utf8mb4），部分組合 emoji 更長。
與字元數區別？
字元數≠位元組數，UTF-8 下需按位元組算儲存/傳輸，避免截斷亂碼。

Formula & Standard References

Item Formula / Rule Source / Standard
Byte-length tiers U+0000–U+007F uses 1 byte, U+0080–U+07FF uses 2, U+0800–U+FFFF uses 3, U+10000–U+10FFFF uses 4 ISO/IEC 10646 / RFC 3629 §3
Surrogate exclusion U+D800–U+DFFF are UTF-16 surrogates and are invalid in UTF-8 Unicode Standard §3.9, Table 3-7
Self-synchronization The count of leading 1 bits in the lead byte equals the total byte length RFC 3629 §3, UTF-8 syntax
