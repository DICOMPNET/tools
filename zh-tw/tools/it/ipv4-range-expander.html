💻 IPv4 Range Expander

IPv4 Range Expander - Expand a CIDR into network, broadcast, usable host count and range. Free, browser-only.

📐 工作原理與說明
地址轉整數：按點號拆成 4 段，段數不為 4 或任一段不是 0 到 255 的合法整數時返回非數；整數 = 第 1 段 × 2²⁴ + 第 2 段 × 2¹⁶ + 第 3 段 × 2⁸ + 第 4 段。整數轉地址：依次取無符號右移 24、16、8 位後與 255 按位與，再加上與 255 按位與的末段，中間以點號連線。輸入按「IP/字首」解析，字首須在 0 到 32 且地址須合法。掩碼 = 字首為 0 時取 0，否則把 0xFFFFFFFF 左移 (32 − 字首) 位後按無符號右移 0 位；網路地址 = 地址與掩碼按位與後按無符號右移；廣播地址 = 網路地址 或 上「掩碼按位取反後按無符號右移」；可用主機數 = 字首大於等於 31 時取 0，否則廣播地址 − 網路地址 − 1。可用範圍取網路地址 + 1 到廣播地址 − 1；字首 31 時說明僅兩個地址常作點對點鏈路，字首 32 時說明為單主機地址
在 IPv4 起止地址與 CIDR 列表之間展開或聚合。
  • 原理：IPv4 可視為 32 位無符號整數，地址範圍即整數區間，展開即逐個遞增。
  • 聚合：把連續區間合併為最少的 CIDR 塊，需按塊大小對齊邊界。
  • 規模：大範圍展開會產生海量條目，應優先用 CIDR 聚合表示。
  • 用途：批次地址清單生成、防火牆與路由規則整理。

⚠️ 使用說明與注意事項
  • 子網掩碼由字首決定：/24 即 255.255.255.0，前 24 位為網路位、後 8 位為主機位。
  • 網路地址 = IP 與掩碼按位與；廣播地址 = 網路地址或上掩碼取反；可用主機 = 總數 − 2（去掉網路與廣播）。
  • /31、/32 是特殊用途（鏈路/單主機），可用主機數為 0，本工具已單獨提示。

❓ 常見問題（FAQ）

跨段範圍能展開嗎？
可以，但地址數極大時建議只取首尾或按需分頁。
範圍很大時會卡嗎？
會。一個 /8 有 1600 多萬個地址，完整展開會耗盡記憶體、瀏覽器也會失去響應。建議優先用 CIDR 表達範圍，只在確實需要逐條處理時才展開，並設定數量上限保護；批次操作應優先考慮用網段規則而非逐 IP 列表。
