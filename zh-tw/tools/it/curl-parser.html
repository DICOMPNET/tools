curl Command Parser

📐 工作原理與說明
先按「雙引號包裹串 / 單引號包裹串 / 非空白串」三種形態做引號感知切詞；再按「選項是否帶值」對映表成對消費引數：-X/--request 取方法，-H/--header 收請求頭，-d/--data/--data-raw/--data-binary/--data-urlencode 取請求體，-F/--form 取表單欄位，-u/-o/-A/-b/-T 等帶值選項只消費值不參與 URL；-G/--get 把資料追加到查詢串（預設 GET），-I/--head 預設 HEAD；未顯式 -X 而帶資料時按 curl 語義預設 POST，-T 上傳預設 PUT；-u/-b/-A/-e 保留為認證、Cookie、User-Agent、Referer 語義；首個非選項詞作為 URL；憑據預設脫敏，所有輸出統一 HTML 轉義，並附結構化 JSON
把 curl 命令解析為結構化的請求資訊。
  • 引數：-X 方法、-H 請求頭、-d/--data 請求體、-F 表單、-u 認證、--compressed。
  • 難點：需正確處理 shell 引號（單/雙引號）與反斜槓續行。
  • 輸出：URL、方法、頭部、請求體，可生成並複製 fetch 或 Python requests 程式碼；認證/Cookie 預設脫敏，需自行替換佔位。
  • 侷限：含 shell 變數或管道的命令無法靜態求值；代理、證書、超時、輸出檔案等無法靜態還原的選項會列在“未納入請求”中。

❓ 常見問題（FAQ）




能轉 Python 嗎？
結合程式碼生成器可轉 requests 片段。


複製出來的命令帶了 --compressed 會有影響嗎？
它只是告訴 curl 自動解壓 gzip/br 響應，不改變請求語義，多數 HTTP 客戶端預設就會發送並解壓，轉換時通常無需對應處理。真正要注意的是 -H 裡的 Cookie 與 Authorization——它們含會話憑據，分享或提交到倉庫前務必刪除。
