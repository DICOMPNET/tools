📐 工作原理與說明
左右文本各自 JSON.parse 後比對，產出路徑級差異列表，按 op 分為 add（新增）、del（刪除）、mod（修改）三類並分別計數，同時統計兩側相同的節點數；差異數為 0 時提示兩個 JSON 完全相同。對比模式分兩種：深度對比遞迴展開每一層（陣列預設按下標逐項對齊），簡單對比只看頂層鍵、巢狀變化合併成一處 mod。勾選「陣列按內容匹配」後，陣列改用「規範序列化鍵 + 最長公共子序列」先對齊相同元素再比對，元素換序不再被報成逐項修改。行級對照把兩側按縮排 2 空格序列化後按行切分，再做逐行差異生成左檢視、右檢視與合併檢視。任一側為空時提示輸入完整
對比兩份 JSON 並標出差異。
  • 方法：遞迴比較兩棵 JSON 樹，標記新增、刪除與值變更的節點。
  • 陣列：預設按索引對齊；勾選「陣列按內容匹配」後按元素內容對齊，後者對元素順序變化更友好。
  • 輸出：變更路徑（如 a.b[0].c）、舊值、新值與變更型別。
  • 用途：介面變更審查、配置比對、迴歸測試斷言。

❓ 常見問題（FAQ）

陣列順序影響對比嗎？
預設按位置比對；勾選「陣列按內容匹配」後改為按元素內容對齊，元素換序不再被報成逐項修改。
為什麼數字 1 和字串 "1" 被判為不同？
因為 JSON 是有型別的，型別不同即視為不同值，這是嚴格比較的預設行為。若只關心結構差異，可開啟「忽略型別」或先做規範化；同時注意 1.0 與 1 這類表示差異，以及物件鍵順序——鍵序在語義上無意義，但樸素文本對比會把它當差異。
