⚙️ JSON to TOML

📐 工作原理與說明
遞迴轉換：把當前層級的鍵分為標量與表兩類——值為非陣列的物件時歸為表，值為「元素全部是物件的非空陣列」時也歸為表（表陣列），其餘歸為標量。先逐行輸出標量（鍵 = 值），再處理表：表陣列為每個元素輸出一對方括號包裹的表頭並遞迴其內容，普通表輸出單個方括號包裹的表頭並遞迴；有字首時完整鍵名以字首加點號連線。鍵名只在匹配 [A-Za-z0-9_-]+ 時按裸鍵輸出，否則用 JSON.stringify 加雙引號，含點、空格或空鍵都不會被誤解析成巢狀表；表頭的每一段同樣逐段引用。縮排下拉決定每層表頭與標量行的前導空白（2 空格 / 4 空格 / Tab），隻影響排版不改變 TOML 語義。TOML 沒有 null 型別，遇到 null 或「物件與標量混排的陣列」時直接報錯，不靜默改寫；字串統一用雙引號包裹並轉義，唯獨嚴格匹配 ISO 8601 的日期、日期時間或時間字串按 TOML 原生日期型別輸出為裸值（月日與時分秒先做範圍校驗，不合格仍按普通字串處理）

❓ 常見問題（FAQ）

巢狀物件怎麼轉？
用 [section] 表層級。
為什麼轉換後順序變了？
TOML 要求「表必須位於所有普通鍵之後」，因此轉換器必須先輸出根級標量、再逐層輸出表頭，看起來順序就被重排了。這是格式約束導致的，不是資料丟失；若需要保持人眼可讀的順序，應在源端就按層級組織好結構。
