📄 JSONPath Query

📐 工作原理與說明
表示式必須以 $ 開頭，否則丟擲「表示式必須以 $ 開頭」的錯誤。去掉開頭的 $ 後切分為記號序列，從只含根節點的集合出發逐級下探：子屬性記號取當前物件中該鍵的值（鍵不存在則跳過）；萬用字元記號把陣列各項或物件各鍵值全部展開；遞迴下探記號在當前子樹中按鍵名或萬用字元收集全部匹配；下標記號支援單個索引（負索引折算為長度加該負數，折算後落在有效範圍才取）、起止區間按步長遍歷（越界跳過、負索引折算後有效才取）以及過濾表示式（逐項求值命中才取）；長度記號取陣列長度或物件的鍵個數。每一級把結果集合整體替換為下一級結果，最終得到匹配陣列。展示時僅一項且為物件則展示該物件，有多項則展示整個陣列，無結果顯示沒有匹配；同時統計匹配項數與查詢耗時（結束時間減開始時間，保留 2 位小數）
用 JSONPath 表示式查詢 JSON 資料。
  • 語法：$ 為根，. 取屬性，[] 取下標，* 通配，.. 遞迴下降。
  • 過濾：[?(@.price < 10)] 按條件篩選陣列元素。
  • 類比：JSONPath 之於 JSON，相當於 XPath 之於 XML。
  • 注意：不同實現（Goessner 原版與各語言庫）在細節上存在差異。
  • 行列號從 1 開始；本頁深度上限 64 層（遞迴下降 .. 超出即停止收集）；輸入上限 不設上限。本頁錯誤提示為文字說明，不含行列號。

📖 JSONPath 語法參考

表示式說明示例
$根節點$ - 整個 JSON
@當前節點@.price - 當前節點的 price
.property子屬性$.user.name
..property遞迴查詢$..id - 所有層級的 id
*萬用字元$.store.* - store 下所有子元素
[index]陣列索引$.items[0]
[start:end]陣列切片$.items[1:3]
[?(expr)]過濾表示式$.items[?(@.price>10)]
length()陣列長度$.items.length()

❓ 常見問題（FAQ）

與 XPath 區別？
JSONPath 面向 JSON，語法更簡潔。
為什麼用 * 通配取不到深層欄位？
因為 * 只匹配一層。$.a.*.c 能取到 a 下一級的 c，更深的層級需用遞迴下降 ..（如 $..c 匹配任意深度的 c）。另外過濾表示式（如 $.items[?(@.price>10)]）並非所有實現都支援，使用前先確認所用庫的語法相容度。
