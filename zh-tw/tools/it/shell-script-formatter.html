⌥ Shell Script Format

📐 工作原理與說明
按行遍歷指令碼並維護縮排深度與 case 塊計數。先用「剝離引號、轉義與行內註釋後的程式碼」探測 here 文件：命中「<< 加定界符」的起始行按當前縮排輸出，定界符支援 'EOF'、"EOF"、\EOF 與 <<-，隨後各行原樣保留（縮排正文會改變 shell 語義），直到出現與定界符相同的行才退出；字串或註釋裡的 << 不觸發；跨行單/雙引號字串同樣逐字保留，壓縮時也不 trim 其內部行。普通行去掉首尾空白後處理，連續空行只保留一個。本行輸出深度：整行是 fi/done/esac、以右花括號開頭、以 else/elif/then/do 開頭，或整行是 ;;/;&/;;& 時減 1（不小於 0）。輸出後狀態深度：fi/done/esac、右花括號與分支終止符減 1；else/elif/then/do 不變（其前的 if/for 已開層）；以 if/for/while/until/case 開頭、行尾為左花括號或整行就是左花括號時加 1；僅在 case 塊內、且「行首到右括號之間無空白/引號/括號、右括號是行尾」的分支模式行也加 1。最終按「縮排單位 × 輸出深度 + 去空白後的行」拼接。壓縮只逐行去首尾空白並刪空行、保留換行，不插入分號；校驗按剝離後的程式碼統計關鍵字與括號，結果寫狀態列且不覆蓋輸出
本開發工具在前端本地完成解析、轉換與處理，程式碼不離開瀏覽器，遵循對應語法與格式規範。 工具名稱：Shell 指令碼格式化 - 免費開發工具，線上Shell 指令碼格式化，免費使用。

❓ 常見問題（FAQ）

格式化會改行為嗎？
不，僅調整空白。
為什麼格式化後腳本報錯了？
Shell 對空白極其敏感：if [ ... ] 裡方括號兩側必須有空格、變數賦值等號兩邊不能有空格、續行符 \ 後不能有任何字元（包括空格）。格式化工具若不熟悉這些規則就可能改壞。因此格式化後必須 shellcheck 檢查、並在測試環境實跑一遍再上線。
