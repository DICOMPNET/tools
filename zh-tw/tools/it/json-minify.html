📐 工作原理與說明
解析輸入 JSON 後重新序列化：壓縮模式輸出緊湊形式，美化模式輸出兩個空格縮排的形式。原始位元組數與輸出位元組數均按 UTF-8 位元組長度計算；壓縮率 = (1 − 輸出位元組數 ÷ 原始位元組數) × 100%，保留 1 位小數（原始位元組數為 0 時取 0）。壓縮模式下壓縮率為負（即輸出反而變大）時提示小體積 JSON 建議保留美化格式。解析失敗時輸出解析失敗原因並清空輸出
壓縮或美化 JSON 文本。
  • 壓縮：移除所有非必要空白與換行，得到最小體積的 JSON。
  • 美化：按層級縮排輸出（常用 2 空格），便於閱讀與 diff。
  • 語法：JSON 要求鍵與字串用雙引號，不允許尾隨逗號與註釋。
  • 語義：壓縮與美化均不改變資料內容，僅改變排版。

要點說明
合法值型別string / number / object / array / true / false / null
鍵與字串必須使用雙引號，單引號不合法
跳脫字元\" \\ \/ \b \f \n \r \t \uXXXX
壓縮本質移除所有無意義空白與換行，不改變語義

常見錯誤：使用單引號、末尾多餘逗號、含註釋、數值帶前導零——均會導致解析失敗。

💡 常見使用場景

  • 與 json-formatter 同類，去空白壓縮。
  • 壓縮介面負載：把去掉縮排的 JSON 作為請求體傳送，減少傳輸位元組，尤其適合高頻呼叫的內部介面。
壓縮
多行 JSON 壓縮為單行，體積通常降 10–30%。

❓ 常見問題（FAQ）

壓縮 JSON 還能解析嗎？
能，合法 JSON 不依賴換行。
壓縮會丟資料嗎？
不會。JSON 規範明確忽略記號之間的空白，鍵名與字串值內部的內容不受影響，去掉縮排、換行與空格後的解析結果完全一致。唯一要小心的是手寫拼接 JSON 時誤刪了字串值內部的空格——那屬於內容而非格式。
