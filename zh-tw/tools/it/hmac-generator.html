#️⃣ HMAC Generator

Generate HMAC signatures (HMAC-SHA256 and more) with a secret key in your browser — verify message integrity.

📐 工作原理與說明
HMAC 訊息認證碼
HMAC(K, m) = H((K′ ⊕ opad) ‖ H((K′ ⊕ ipad) ‖ m))
K′ 為金鑰填充至分組長度（短則補 0，長則先雜湊）
opad = 0x5c 重複，ipad = 0x36 重複
實現：Web Crypto API importKey('raw', key, {name:'HMAC', hash:algo}) 後 sign
支援演算法隨瀏覽器而異（SHA-1/SHA-256/SHA-384/SHA-512）
生成基於金鑰的訊息認證碼（HMAC）。
  • 公式：HMAC(K,m) = H((K⊕opad) ∥ H((K⊕ipad) ∥ m))，定義於 RFC 2104。
  • 與雜湊區別：HMAC 需要金鑰，可同時驗證完整性與訊息來源；普通雜湊任何人都能算出。
  • 輸出：長度等於底層雜湊的摘要長度，如 HMAC-SHA256 為 256 bit。
  • 用途：API 簽名、Webhook 校驗、JWT 的 HS256 演算法。

📖 演算法說明

HMAC (Hash-based Message Authentication Code) 用於驗證訊息完整性和真實性。

公式：HMAC(K, m) = H((K ⊕ opad) || H((K ⊕ ipad) || m))

💡 常見使用場景

  • 用金鑰對訊息生成認證碼，驗證完整性與來源。
  • 對接第三方 Webhook：用對方給的金鑰對原始報文體計算 HMAC，與請求頭裡的簽名比對，確認報文來源與完整性。
HMAC-SHA256
key="secret", msg="hello" → HMAC-SHA256 = 88da81...（任何改動都會使 MAC 失配）。

❓ 常見問題（FAQ）

HMAC 需要保密金鑰嗎？
是，金鑰必須保密，否則可偽造 MAC。
為什麼簽名對不上？
三個高頻原因：一是參與簽名的不是原始報文體而是解析後的物件（空格與鍵序已變），必須用收到的原始位元組；二是金鑰帶了多餘空白或換行；三是編碼不一致（十六進位制 vs Base64）。時間戳與 nonce 是否參與拼接也要與文件逐字對齊。
