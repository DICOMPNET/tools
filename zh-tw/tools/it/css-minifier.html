🧹 CSS Compress / Beautify

📐 工作原理與說明
按選項處理：先把字串（單雙引號）與 url(...) 切成受保護片段，改寫只作用於程式碼片段，字串與 url 內的空白、逗號、冒號原樣保留；開啟移除註釋時再刪掉塊註釋。隨後把連續空白壓縮為單個空格，把左花括號連同兩側空白替換為「空格 + 左花括號 + 換行 + 縮排」，把分號及其後空白替換為「分號 + 換行 + 縮排」，把逗號及其後空白替換為「逗號 + 空格」，把右花括號連同兩側空白替換為「換行 + 右花括號 + 兩個換行」，最後合併連續空行。縮排按選項取製表符或指定數量的空格
壓縮或美化 CSS 程式碼。
  • 壓縮：刪除註釋與多餘空白、去掉最後一條宣告的分號、縮寫顏色（#ffffff → #fff）。
  • 美化：反向格式化，按規則縮排換行，便於閱讀與 diff。
  • 風險：激進壓縮可能影響 CSS hack（如 * _ 字首）與 @media 語義，需迴歸測試。
  • 收益：減小體積、加快解析；與 gzip/brotli 壓縮疊加使用效果更佳。

📖 使用說明

功能說明

  • 美化格式化：統一縮排、換行，使CSS結構清晰易讀
  • 壓縮：移除所有註釋、空白、換行，生成最小體積CSS
  • 壓縮率統計：即時顯示壓縮前後體積對比
  • 歷史記錄：自動儲存處理記錄，可快速恢復

壓縮最佳化項

  • 移除 /* comments */ 註釋
  • 移除多餘空白字元和換行
  • 移除最後一個分號
  • 保留必要空格（選擇器之間）
  • 顏色值最佳化（如 #ffffff → #fff）

❓ 常見問題（FAQ）

壓縮影響除錯嗎？
會，生產用壓縮、開發用原始檔。
為什麼要配合 source map？
壓縮後所有規則擠在一行，瀏覽器 DevTools 裡看到的位置無法對應原始碼。生成 .map 檔案並在產物末尾保留對應註釋，DevTools 就能映射回原始檔案與行號，定位問題時不必先切回未壓縮版本。
