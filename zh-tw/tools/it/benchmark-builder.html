📐 工作原理與說明
吞吐率 = 運算元 × 1000 ÷ 實際耗時(ms)（ops/s）；五種負載：int 500 次平方累加、float 三角函式開方、str 100 次串拼、array 200 元素推入+降序排序、object 200 鍵寫入；評級：＞100萬 極快 / ＞10萬 很快 / ＞1萬 正常 / ＞1000 偏慢 / 其餘較慢
對多個候選實現做可復現的效能對比，輸出統計指標。
  • 取樣：每個候選重複執行 N 次，記錄耗時，統計均值、中位數、標準差與百分位。
  • 預熱：先跑若干輪 warmup 讓 JIT 完成最佳化再正式計時，避免冷啟動偏差。
  • 計時：用 performance.now()（單調高精度時鐘）而非 Date.now()。
  • 干擾：瀏覽器後臺節流、GC 停頓與其他標籤頁負載都會汙染結果，應多輪取穩定值。

📚 深度解析：Benchmark 基準測試

💡 常見使用場景

  • 對比兩段程式碼的吞吐/耗時，定位效能瓶頸。
  • 對比兩種實現：把陣列去重的 Set 方案與 filter + indexOf 方案各跑若干輪，用中位數而非均值判斷優劣——均值更容易被 GC 停頓等偶發尖刺拉偏。
對比
對 1e6 整數分別用 `for` 累加與 `sum()`，輸出各自 ops/sec 與相對倍數。

❓ 常見問題（FAQ）

為何要預熱？
JIT/快取使首次偏慢，預熱後測值更穩。
為什麼每次跑結果都不一樣？
JIT 編譯、CPU 頻率動態調整、垃圾回收與其他程序爭搶都會引入波動。可靠做法是：先 warmup 若干輪讓 JIT 穩定，再重複取樣足夠多次，報告中位數與百分位（p95/p99），並在同一臺機器、相近負載下比較；只看單次執行的數字沒有意義。
