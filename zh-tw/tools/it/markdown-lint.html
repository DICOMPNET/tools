📝 Markdown Linter

Markdown Linter - Check heading levels, list formatting, link syntax and duplicate headings, with fix suggestions. Free, browser-only.

📐 工作原理與說明
按行掃描 Markdown：圍欄程式碼塊（``` / ~~~）內的行跳過標題、列表、行尾與行寬檢查，首個圍欄未標註語言記 MD040；匹配一到六個井號加空格開頭的標題行記錄級別，比上一個標題級別大 1 以上記標題跳級，去掉井號後的標題文本重複出現記標題重複；行首（允許前導空白）為連字元或星號且緊接非空白、且整行不是成對強調語法（*斜體* / **加粗** / _斜體_）時，記列表符號後缺空格；逐行匹配方括號連結語法，空地址記空連結地址；行尾有多餘空格記 MD009，行寬超過 80 列記 MD013。輸出總行數與問題數，並逐條列出問題所在行號與描述
檢查 Markdown 文件的規範與風格問題。
  • 檢查項：標題跳級 / 重複標題、列表符號後缺空格、空連結地址、行尾多餘空格（MD009）、行寬超過 80 列（MD013）、圍欄程式碼塊未標註語言（MD040）；圍欄程式碼塊內的內容不參與標題與列表檢查。
  • 常見問題：一級標題後直接跳三級、同一文件多個一級標題、連結與圖片缺少說明。
  • 規則集：對照 markdownlint 編號規則，已實現 MD001 標題層級、MD009 行尾空格、MD013 行寬、MD040 程式碼塊語言；MD007 列表縮排、MD041 首行標題留給團隊規範。
  • 價值：統一文件風格，提升可讀性與長期可維護性。

⚠️ 使用說明與注意事項
  • 標題建議從 H1 起逐層遞增，跳級會影響文件大綱與 SEO 錨點。
  • 無序列表 `-`/`*` 後需一個空格；有序列表 `1. ` 後也需空格，否則不渲染為列表。
  • 本檢查為風格輔助，不覆蓋 CommonMark 全部語法；匯出前仍建議用官方解析器預覽。

❓ 常見問題（FAQ）

規則可配嗎？
多數 linter 支援配置檔案停用規則。
為什麼它報的問題看起來不重要？
因為 lint 檢查的是「一致性與可維護性」而非「正確性」：行尾空格、標題前後空行、列表縮排統一，單看都不影響渲染，但混在一起會讓 diff 噪音變大、多人協作難以對齊。可按團隊習慣關掉部分規則，但建議至少保留結構類規則。
