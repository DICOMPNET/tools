🔤 Punycode Encode/Decode

📐 工作原理與說明
先收集碼點小於 0x80 的字元作為基本字元並直接拼接，基本字元數大於 0 時在其後補一個連字元；再收集碼點大於等於 0x80 的字元作為擴充套件字元。隨後進入自適應編碼迴圈：取當前未處理字元中最小的不小於 n 的碼點 m，把 delta 加上「(m − n) × (已處理數 + 1)」，令 n 等於 m；再逐字元更新 delta（小於 n 時 delta 加 1，等於 n 時按基數與自適應偏置做變長整數編碼），用數字字元表逐位輸出編碼字元，直到全部擴充套件字元處理完畢
國際化域名（IDN）的 Punycode 編解碼。
  • 用途：DNS 只支援 ASCII，含非 ASCII 字元的域名必須轉寫為 Punycode 才能解析。
  • 編碼：保留原有 ASCII 部分，非 ASCII 部分按演算法壓縮為字母數字串。
  • 字首：轉換結果以 xn-- 開頭，如「中國」→ xn--fiqs8s。
  • IDNA：實際域名系統使用 IDNA 規則，先做名稱預處理再做 Punycode 編碼。

Encode and decode Punycode (RFC 3492) for internationalized domain names (IDN) directly in your browser.

📖 演算法說明

Punycode 用於 IDN 域名轉換，將非 ASCII 域名轉為 ASCII。

例如: 中文.com → xn--fiqs8s.com

📚 深度解析：Punycode 編解碼

💡 常見使用場景

  • 把含中文的域名（如 中文.com）編碼為 ASCII 以相容 DNS。
  • 給中文域名備案或配置 DNS 時轉成 xn-- 形式，因為 DNS 系統本身只接受 ASCII 字元。
編碼 "中文"
輸入 `中文` → 輸出 `xn--fiq228c`（即域名標籤 `xn--fiq228c`）。

❓ 常見問題（FAQ）

瀏覽器位址列為何顯示中文？
瀏覽器解碼 Punycode 後展示 Unicode，但底層 DNS 仍用 xn-- 形式。
為什麼要警惕同形異義域名？
因為不同語言的字元可能長得幾乎一樣（如西里爾字母 а 與拉丁字母 a），攻擊者可註冊外觀相同但碼點不同的域名做釣魚。因此瀏覽器對 IDN 有顯示策略：若混用了多種文字，往往直接顯示 Punycode 而非原文。企業應為品牌域名註冊常見變體。
