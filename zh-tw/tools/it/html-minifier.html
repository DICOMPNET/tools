📦 HTML Compressor

📐 工作原理與說明
先把 pre、textarea、script、style 這幾類標籤的整塊內容抽取出來替換為佔位符保護起來（記錄順序以便還原）。開啟移除註釋時刪除 HTML 註釋，但保留以條件註釋開頭的部分。開啟摺疊空白時按字元狀態機逐節點處理：標籤與屬性值原樣穿過，文本節點內的連續空白摺疊為單個空格；安全模式只在塊級標籤邊界刪除空白、在行內元素邊界保留一個空格（避免 span/strong 等粘連），非安全模式額外刪除標籤之間的純空白文本。最後去掉首尾空白並把佔位符還原為原始塊內容。壓縮率 = (1 − 輸出長度 ÷ 原始長度) × 100%，保留 1 位小數（原始長度為 0 時取 0），並展示原始大小、輸出大小與壓縮率
壓縮 HTML 以減小體積。
  • 手段：刪除註釋與多餘空白、去掉可選閉合標籤、省略可省的屬性引號。
  • 例外：<pre> 與 <textarea> 內的空白具有語義，必須保留。
  • 內聯資源：內聯 JS/CSS 的壓縮需要對應解析器，否則可能破壞程式碼。
  • 收益：HTML 通常已被 gzip/brotli 壓縮，需實測確認邊際收益。

💡 常見使用場景

  • 去除註釋/空白/可選標籤減小體積。
  • 壓縮郵件或 AMP 頁面：這類場景對體積敏感且不含互動指令碼，壓縮後能明顯減少傳輸位元組。
壓縮
`<html> <body><!--c--><p>x</p> </body></html>` → `<html><body><p>x</p></body></html>`。

❓ 常見問題（FAQ）

會破壞結構嗎？
合規壓縮不會，但需保留 pre/textarea 內空白。
為什麼壓縮後頁面顯示變了？
最常見是空白被刪導致行內元素間距變化——HTML 會把標籤間的換行渲染成一個空格，刪掉後相鄰元素就貼在一起了。其次是 <pre>/<textarea> 內的空白被誤刪，以及未閉合的可選標籤（如 </li>）被移除後影響 CSS 選擇器。壓縮後務必做視覺迴歸。
