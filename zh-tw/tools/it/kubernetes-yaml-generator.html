📐 工作原理與說明
應用名取輸入值（為空時用預設名），映象取輸入值（為空時用預設映象），埠取輸入值向下取整（無效時取 80），副本數取輸入值向下取整並保證至少為 1。按模板拼裝 Kubernetes 清單：Deployment 段依次寫入介面版本、資源型別、應用名、副本數、以應用名為值的標籤選擇器，以及容器名、映象與容器埠；隨後以分隔線接 Service 段，寫入介面版本、資源型別、應用名、以應用名為值的選擇器、服務埠與目標埠（二者同為上述埠值）與叢集內訪問型別。輸出時對整段 YAML 做 HTML 轉義後在程式碼塊中展示
生成 Kubernetes 資源清單 YAML。
  • 必填欄位：apiVersion、kind、metadata、spec。
  • 關聯：Deployment 的 selector 必須與 Pod template 的標籤匹配；Service 通過 selector 選中 Pod。
  • 資源：requests 決定排程，limits 決定使用上限，二者應合理設定。
  • 建議：同時配置 readiness/liveness 探針，避免流量打入未就緒的 Pod。

⚠️ 使用說明與注意事項
  • image: latest 不利於回滾與可重現部署，生產應鎖定具體版本/tag 或 digest。
  • Service 的 targetPort 須與容器 containerPort 一致；對外暴露需改 type: NodePort/LoadBalancer 或接 Ingress。
  • 生成後 kubectl apply -f 部署；變更映象建議走滾動更新與探針（liveness/readiness）保障可用性。

❓ 常見問題（FAQ）

如何暴露外網？
Service 改 NodePort/LoadBalancer 或加 Ingress。
為什麼要配 readiness 與 liveness 探針？
二者作用不同：liveness 判斷容器是否存活，失敗會重啟；readiness 判斷能否接收流量，失敗會把它從 Service 後端摘除但不重啟。只配 liveness 會讓啟動慢的服務被反覆殺死；二者配合才能做到啟動期間不接流、死鎖後自動恢復。
