📐 工作原理與說明
按點號切分令牌，段數不為 3 判為格式錯誤。解碼採用 base64url：先把 - 換成 +、_ 換成 /，再補 = 至長度為 4 的倍數，atob 解出位元組後逐位元組轉成 %HH 再做 decodeURIComponent，從而正確還原 UTF-8 中文。校驗：當前秒數 = ⌊Date.now() ÷ 1000⌋；有 exp 且當前時間 > exp 判已過期，否則剩餘時間拆為天 = ⌊剩餘 ÷ 86400⌋、小時 = ⌊(剩餘 mod 86400) ÷ 3600⌋；有 nbf 且當前時間 < nbf 判尚未生效；iat 等時間欄位同時按 值 × 1000 轉本地時間展示。
解析並除錯 JWT，檢視宣告與簽名校驗狀態。
  • 解析：拆分三段並對前兩段做 Base64url 解碼，展示 Header 與 Payload 宣告。
  • 時間宣告：exp（過期）、iat（簽發）、nbf（生效前無效）均為 Unix 秒。
  • 校驗：HS256 需金鑰做 HMAC 比對；RS256 需公鑰驗籤。
  • 安全：請勿在不受信環境中貼上真實生產令牌或金鑰。

📖 JWT 說明

    

      
JWT 結構

      
JWT由三部分組成，用點(.)分隔：

      
    
        
  • Header：演算法和token型別，Base64Url編碼
    • 
        
  • Payload：宣告(claims)，包含使用者資料和標準欄位，Base64Url編碼
    • 
        
  • Signature：簽名，驗證資料完整性
    • 
      

    

    

      
標準 Claims

      
    
        
  • iss (issuer)：簽發者
    • 
        
  • sub (subject)：主題/使用者ID
    • 
        
  • aud (audience)：接收方
    • 
        
  • exp (expiration)：過期時間（Unix時間戳）
    • 
        
  • nbf (not before)：生效時間
    • 
        
  • iat (issued at)：簽發時間
    • 
        
  • jti (JWT ID)：唯一標識
    •

貼上 `eyJ...` → 展示 header/payload；輸入 secret 驗證簽名是否匹配（HS256）。


❓ 常見問題（FAQ）




能離線驗籤嗎？
HS 用對稱金鑰可離線；RS 需公鑰。


為什麼驗籤通過了業務還是拒絕？
驗籤只證明令牌未被篡改，業務還需自行校驗宣告：exp（是否過期）、nbf（是否未生效）、iss/aud（簽發方與受眾是否匹配），以及自定義的許可權欄位。此外服務端通常還有令牌黑名單或版本號校驗，這些都不在驗籤範圍內。
