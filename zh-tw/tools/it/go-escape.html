🔤 Go String Escape

📐 工作原理與說明
先去掉首尾空白；以反引號開頭且以反引號結尾時直接取反引號之間的內容原樣輸出。否則存在成對外層雙引號或單引號時去掉外層引號。逐字元掃描：遇到反斜槓且後面還有字元時，按後隨字元轉義——a 轉響鈴、b 轉退格、f 轉換頁、n 轉換行、r 轉回車、t 轉製表符、v 轉縱向製表符、反斜槓與單雙引號轉其自身；x 取後隨 2 位十六進位制、u 取後隨 4 位、U 取後隨 8 位，按 16 進位制解析為碼點；後隨字元是八進位制數字時，連續取最多 3 位八進位制數字按 8 進位制解析為碼點；其餘情況取後隨字元本身。不是轉義序列的字元原樣保留
Go 字串字面量的轉義與反轉義。
  • 兩種字面量：雙引號為可跳脫字元串，反引號（`）為原始字串，後者不做任何轉義。
  • 轉義序列：\n \t \r \" \\ \uXXXX \xHH \OOO（八進位制）。
  • 原始字串：可跨行書寫，適合正則、SQL 與路徑；但不能包含反引號本身。
  • 差異：Go 的 \x 固定取兩位十六進位制，與 C 的貪婪解析不同。

Escape and unescape Go string literals in your browser, handling \n, \t and unicode escapes.

❓ 常見問題（FAQ）

Go 原生字串 `...` 呢？
反引號原生串不處理轉義，但無法包含反引號本身。
\u 和 \x 轉義有什麼區別？
\x41 按單位元組表示，只適合 ASCII；\u00e9 與 \U0001F600 按 Unicode 碼點表示，可表達任意字元。Go 原始檔本身就是 UTF-8，中文通常可直接書寫，無需轉義；只有在需要避免編輯器或傳輸環節破壞位元組時才用碼點形式。
