📐 工作原理與說明
解析輸入 JSON 後按型別確定表頭與行：陣列且元素為物件時，表頭取所有元素鍵名的並集，每行按表頭順序取值，值為 undefined 或 null 時轉為空串；陣列但元素不是物件時按單列 value 輸出；普通物件時表頭取其鍵名並只輸出一行；其餘標量按單列 value 輸出。欄位轉義：開啟全部加引號，或欄位中包含分隔符、引號字元、換行、回車時加引號；加引號時把欄位內的引號字元全部替換為兩個引號字元。開啟表頭時先輸出表頭行，再逐行以分隔符連線輸出，行與行之間以換行連線
把 CSV 轉換為 JSON 陣列。
  • 解析：按分隔符與引號規則切分，首行作欄位名，每行生成一個物件。
  • 型別：可選擇把純數字與 true/false 自動轉為對應型別，或全部保留字串。
  • 分隔符：支援逗號、製表符、分號；需正確處理引號包裹與轉義雙引號。
  • 異常：資料行欄位數多於表頭時直接報錯並給出行號，不靜默丟列；少於表頭時缺列補空串。

JSON 標準
  • CSV: Comma-Separated Values，逗號分隔值，是一種簡單的檔案格式，用於儲存表格資料
  • JSON: JavaScript Object Notation，是一種輕量級的資料交換格式，易於人閱讀和編寫
  • RFC 4180: CSV 的正式標準，規定了換行符、引號、轉義等規則
  • TSV: Tab-Separated Values，製表符分隔值，另一種常見的表格資料格式
  • 轉義規則: 欄位中包含分隔符、引號或換行符時，需要用引號包裹並轉義內部引號

❓ 常見問題（FAQ）

表頭缺失怎麼辦？
可用列索引 c1,c2… 作為鍵。
數字和日期怎麼變了？
CSV 是無型別的，所有值都是字串。轉換時若自動推斷型別，可能把手機號變成數字而丟失精度，或把 010 變成 10、把 2024-01-02 解析成日期物件。需要保真時應關閉型別推斷，或在轉換後按欄位名顯式指定型別。
