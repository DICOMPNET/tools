💻 Code Line Counter

📐 工作原理與說明
按所選語言（選擇自動時按 JavaScript 處理）取該語言的行註釋規則與塊註釋規則，逐行掃描：去除空白後為空的行計入空行；處於塊註釋中時本行計入註釋行，並在本行找到塊註釋結束符時退出塊註釋狀態（結束符之後還有內容則按剩餘內容重新判定）；否則先判斷是否以某個行註釋符開頭，再判斷是否進入塊註釋——命中塊註釋開始符且其後同一行內沒有結束符時進入塊註釋狀態。既不是註釋也未進入塊註釋的行計入程式碼行。總行數為全部行數，程式碼佔比 = 程式碼行 ÷ 總行數 × 100%（總行數為 0 時取 0），保留 1 位小數
統計程式碼的總行數、程式碼行、註釋行與空行。
  • 維度：總行數、程式碼行、註釋行、空行，可按語言或目錄彙總。
  • 註釋識別：行註釋（//、#）與塊註釋（/* */、三引號），依語言規則判定。
  • 陷阱：字串或正則字面量中出現的 //、/* 不應被誤判為註釋。
  • 解讀：行數可用於規模估算，但不等於工作量或複雜度。

💡 常見使用場景

  • 統計專案程式碼行/註釋/空行。
  • 專案規模度量：統計有效程式碼行、註釋行與空行，估算工作量或跟蹤重構後的刪減量。

❓ 常見問題（FAQ）

算註釋行嗎？
可單獨統計註釋與空行。
行數能代表開發效率嗎？
不能，它只反映程式碼規模。刪除冗餘程式碼會減少行數卻提升質量，用不同語言或風格實現同一功能行數也可能相差數倍。合理的用法是看趨勢與構成（註釋率、單檔案長度），而不是拿它考核產出。
