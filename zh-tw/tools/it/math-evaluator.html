📐 工作原理與說明
數學表示式安全求值
字元白名單校驗：僅允許數字、+-*/%^()., 空格與函式名字母
識別符號白名單：僅放行 sin/cos/tan/sqrt/abs/ln/log/floor/ceil/round/min/max/pi/e，並拒絕成員訪問（如 .constructor）
語法轉換：^ → **（冪運算）；數字後 % 且其後緊跟運算元起始符（數字、小數點、左括號、一元正負號、常量 pi/e 或函式名）時保留為取模運算子（JS %），其餘情況（後接乘除/冪等運算子、右括號或結尾）視為百分比 → (數字/100)；支援小數百分比（如 .5% → 0.005）；約定歧義寫法 50%+3 按取模 50 % 3 處理，需「百分比加數」請顯式寫 (50/100)+3
校驗通過後才交給 new Function 求值，非法識別符號與屬性鏈一律拒絕
長度限制 ≤200 字元；結果非有限數或拋錯 → 提示表示式無效
解析並計算數學表示式的值。
  • 優先順序：先括號，再函式與冪，其次乘除，最後加減。
  • 演算法：常用排程場演算法（Shunting-yard）把中綴式轉為字尾式再求值，避免歧義。
  • 支援：三角函式、對數、開方、取模與常量 π、e。
  • 安全：絕不可用 eval() 執行使用者輸入，應使用專門的表示式解析器。

❓ 常見問題（FAQ）

支援哪些函式？
常見 sqrt、pow、sin/cos、log、abs、round 等。
為什麼 0.1 + 0.2 不等於 0.3？
因為二進位制浮點無法精確表示十進位制的 0.1，二者相加的結果與 0.3 的浮點表示有極小差異。這是 IEEE 754 的固有特性，不是計算錯誤。涉及金額或需要精確比較時，應使用定點數、整數分單位或專門的十進位制庫，比較時用容差而非等號。
