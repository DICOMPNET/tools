📝 INI Parser

📐 工作原理與說明
解析：跳過空行與以 ; 或 # 開頭的註釋行；以 [ 開頭且以 ] 結尾的行視為節名並新建該節的空物件（同名節已存在時合併到該物件，同鍵由後出現的值覆蓋）；其餘行取第一個 = 作為鍵值分隔符，左側為鍵、右側為值，均去首尾空白；有當前節時寫入該節，否則寫入根級。反向輸出：值為普通物件時先寫 [節名]，再逐行寫「子鍵 = 值」，節末補一個空行；非物件直接寫「鍵 = 值」，最後整體去首尾空白
本開發工具在前端本地完成解析、轉換與處理，程式碼不離開瀏覽器，遵循對應語法與格式規範。 工具名稱：INI 解析器 - 免費開發工具，線上INI 解析器，免費使用。

💡 常見使用場景

  • 解析 [section] key=value 配置。
  • 讀取老系統配置：把 .ini 解析成鍵值結構後改一項再寫回，便於指令碼批次修改配置。
解析
`[db] host=localhost` → {db:{host:"localhost"}}。

❓ 常見問題（FAQ）

重複鍵怎麼辦？
後值覆蓋前值（視實現）。
INI 有標準格式嗎？
沒有正式標準，只有廣泛約定：方括號表示節、= 或 : 分隔鍵值、# 或 ; 表示註釋。不同實現在引號處理、大小寫敏感性、是否支援巢狀與多行值上差異很大；跨語言交換配置時建議改用 JSON / YAML / TOML。
