📏 String Length Counter

Count characters, bytes, lines, words and spaces.

📐 工作原理與說明
字元數按 Unicode 碼點陣列的長度統計；位元組數按 UTF-8 編碼後的位元組數統計；行數在文本為空時取 0，否則按換行（相容回車換行、回車、換行）切分後的行數；詞數在去空白後為空時取 0，否則按空白切分後的段數；空格數按空白字元匹配計數；中文字元按中日韓統一表意文字區間匹配計數；標點按中日韓標點、全形區、通用標點區與 ASCII 標點區間匹配計數。平均位元組數 = 位元組數 ÷ 字元數（字元數為 0 時取 0），保留 2 位小數；數值展示時按中文地區千分位格式輸出
統計文本的字元數、位元組數、詞數與行數，是內容與介面限長校驗的常用工具。
  • 字元 vs 碼元：JS 的 .length 計的是 UTF-16 碼元，emoji 與部分生僻漢字佔 2 個碼元。
  • 準確計數：用 [...str].length 或 Intl.Segmenter 按字素簇切分更符合直覺。
  • 位元組數：取決於編碼，UTF-8 下英文 1 位元組、常用中文 3 位元組、emoji 常 4 位元組。
  • 詞數：英文按空白與標點切分；中文需分詞，常用字數與字元數近似。

📌 統計規則
  • 字元數：Unicode 碼點數量（含空格、換行、標點）。
  • 位元組數：按 UTF-8 編碼計算，中文通常佔 3 位元組。
  • 詞數：按空白分隔的連續非空白片段計數。
  • 行數：按換行符分割，空文本計為 0 行。

❓ 常見問題（FAQ）

字元數與位元組數為何不同？
中文等多位元組字元在 UTF-8 佔多位元組，資料庫常按位元組限制。
為什麼 emoji 長度算出來是 2？
因為 JS 字串的 .length 統計的是 UTF-16 碼元，而 emoji 大多位於輔助平面、需兩個碼元（代理對）表示。要得到「人眼看到的字元數」，應遍歷 [...str] 或用 Intl.Segmenter 按字素簇計數；統計傳輸體積則要看 UTF-8 位元組數。
