📄 XML Validator

XML Validator - Check XML for well-formedness: tag pairing, quoted attributes and illegal characters, with error location. Free, browser-only.

📐 工作原理與說明
輸入為空時提示請貼上 XML 內容。用 XML 解析器按 XML 型別解析文本：若文件中存在解析錯誤節點則判定格式錯誤並展示錯誤詳情；否則判定 XML 格式良好，並給出根元素名與文件中的元素總數。解析過程丟擲異常時展示異常資訊
校驗 XML 文件是否規範。
  • 檢查項：標籤是否閉合、巢狀是否正確、屬性值是否加引號、特殊字元是否轉義、是否有唯一根元素。
  • 兩個層次：well-formed 指符合 XML 語法；valid 指還滿足 DTD 或 XSD 約束。
  • 常見錯誤：未轉義的 &、標籤大小寫不一致、缺少根元素、屬性未加引號。
  • 用途：介面資料與配置檔案的合法性檢查。
  • 行列號從 1 開始（首個字元 = 第 1 行第 1 列，取自瀏覽器 DOMParser 的報錯文本）；本頁深度上限 不設上限；輸入上限 不設上限。

⚠️ 使用說明與注意事項
  • XML 與 HTML 不同：所有標籤必須閉合，屬性必須用引號包裹，大小寫敏感，且只能有一個根元素。
  • DOMParser 在瀏覽器環境可解析，但不同引擎報錯資訊措辭不同；生產校驗建議用專用 XML 校驗器（如 xmllint）。
  • 注意 XML 宣告 `` 應位於檔案第一行，前面不能有空行或 BOM。

❓ 常見問題（FAQ）

XML 區分大小寫嗎？
區分，<A> 與 <a> 是不同標籤。
well-formed 和 valid 有什麼區別？
well-formed 指語法正確（標籤閉合、巢狀正確、屬性加引號、有且僅有一個根元素）；valid 指還符合某個 DTD 或 XSD 定義的結構約束（哪些元素允許出現、次序與型別）。本工具校驗的是前者；要做後者需提供對應的 schema 定義。
