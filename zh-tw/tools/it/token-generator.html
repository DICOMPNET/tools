🔑 Random Token Generator

Produce random API tokens, secrets and keys in your browser with adjustable length and character sets.

📐 工作原理與說明
長度取輸入值（非法時取 32），並限制在 4 到 256 之間；數量取輸入值（非法時取 1），並限制在 1 到 20 之間。字元集按勾選的大寫字母、小寫字母、數字、符號四類依次拼接，一類都沒選時提示請至少選擇一種字元集。每個令牌用加密級隨機數填充一個長度不小於指定長度的無符號 32 位陣列，逐位取隨機數對字元集長度取餘，用餘數在字元集中取字元拼接。資訊熵 ≈ 長度 × log₂(字元集大小)，結果四捨五入取整，並展示生成的個數與位數
生成高強度隨機令牌。
  • 隨機源：必須使用 crypto.getRandomValues 等密碼學安全隨機源。
  • 熵要求：常見 128 位以上（如 32 個十六進位制字元）才能抵禦暴力猜測。
  • 用途：會話標識、API 令牌、CSRF 令牌、密碼重置連結。
  • 實踐：令牌應設定有效期、儘量一次性使用，並在服務端安全儲存與校驗。
字元集：

🔒 隨機數來自 crypto.getRandomValues，僅在本機生成，不上傳。

💡 常見使用場景

  • 生成 API Key、CSRF Token 等。
  • 給新接入方簽發 API Key：生成足夠長的隨機令牌後只展示一次，服務端僅儲存其雜湊值。
生成
32 位元組十六進位制 Token 例：`a1b2c3...`(64 位十六進位制)。

❓ 常見問題（FAQ）

Token 要多少熵？
敏感場景至少 128 位隨機性。
生成後該怎麼儲存？
服務端應只存雜湊（如 SHA-256），明文僅在建立時返回一次——這樣即使資料庫洩露也不會直接得到可用令牌。同時應支援吊銷、按字首標識用途、並設定有效期。切勿把令牌寫進前端程式碼、日誌 URL 或倉庫；日誌中展示時應做脫敏（只留前幾位）。
