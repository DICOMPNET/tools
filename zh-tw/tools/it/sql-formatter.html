🗄️ SQL Format

📐 工作原理與說明
先刪除行註釋（雙橫線到行尾）與塊註釋，再把連續空白壓縮為單個空格並去掉首尾空白。隨後按子句關鍵字列表（SELECT、FROM、WHERE、GROUP BY、ORDER BY、HAVING、LIMIT、OFFSET、各種 JOIN、UNION ALL、UNION、ON、VALUES、SET）依次把「關鍵字」（按詞邊界、忽略大小寫，關鍵字內部空格按空白匹配）替換為「換行 + 大寫關鍵字 + 換行 + 縮排」，並把每個逗號及其後空白替換為「逗號 + 換行 + 縮排」。再逐行處理：以主要關鍵字開頭的行保持原樣，其餘非空行且尚未以縮排開頭時補上縮排。開啟關鍵字大寫時，對關鍵字列表做整詞、忽略大小寫的替換為其大寫形式。最後合併連續空行並去掉首尾空白
格式化 SQL 語句，提升可讀性。
  • 處理：關鍵字統一大小寫，主要子句（SELECT、FROM、WHERE、JOIN 等）各佔一行並縮排。
  • 語義：格式化只改排版，不改變執行語義與結果。
  • 風格：關鍵字大寫或小寫依團隊約定；複雜條件與子查詢做層級縮排。
  • 用途：統一 SQL 書寫風格，便於程式碼評審與問題排查。

📖 使用說明

支援的SQL方言

  • 標準SQL：ANSI SQL通用格式
  • MySQL：MySQL特有語法（反引號、LIMIT等）
  • PostgreSQL：PostgreSQL特有語法
  • SQL Server：T-SQL語法（TOP、方括號等）
  • SQLite：輕量資料庫SQL語法

格式化特性

  • 關鍵字自動大寫/小寫
  • SELECT欄位換行對齊
  • FROM/JOIN/WHERE/GROUP BY/ORDER BY等子句換行
  • 縮排對齊，可讀性強
  • 壓縮模式：移除所有空白，生成緊湊SQL

📚 深度解析：SQL 格式化/美化

💡 常見使用場景

  • 把長 SQL 按關鍵字換行縮排。
  • 審查別人寫的長 SQL：格式化後看清 JOIN 層級與 WHERE 條件，便於發現多餘關聯或條件寫錯。
格式化
`select a,b from t where c=1` → 多行 `SELECT a, b FROM t WHERE c = 1`。

❓ 常見問題（FAQ）

會改變執行計劃嗎？
不會，僅調整空白與大小寫。
格式化後結果變了是怎麼回事？
純格式化不會改變語義，但要注意兩點：一是註釋裡的最佳化器提示（如 /*+ INDEX(...) */）若被移動或刪除，會直接影響執行計劃；二是某些方言裡換行位置會影響語義。格式化後建議對比關鍵查詢的執行計劃。
