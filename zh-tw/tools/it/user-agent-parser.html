🌐 User-Agent Parser

📐 工作原理與說明
用規則集分別匹配瀏覽器名與版本號、作業系統、裝置型別與排版引擎；瀏覽器顯示串 = 有版本號時為「名稱 版本」，否則僅名稱；結果區同時給出 UA 字串的字元數長度，輸入為空時隱藏結果區與詳情區
解析 User-Agent 字串中的瀏覽器與裝置資訊。
  • 內容：UA 通常含瀏覽器及版本、渲染引擎、作業系統與裝置型別標識。
  • 方法：通過特徵串正則匹配推斷（如 Chrome/120、Windows NT 10.0、iPhone）。
  • 侷限：UA 可被隨意偽造，各廠商格式不統一，解析結果僅供參考。
  • 趨勢：瀏覽器正推進 UA 凍結，逐步改用 Client Hints（Sec-CH-UA）獲取資訊。

💡 UA 字串結構

典型 UA 格式：
Mozilla/5.0 (平台; 系统信息) 引擎/版本 浏览器/版本

歷史原因：現代 UA 都以 "Mozilla/5.0" 開頭，是瀏覽器大戰時代為相容舊網站留下的"相容性標記"，並非真實身份。

提示：自 2020 年起，Chrome、Firefox、Safari 開始降低 UA 字串的精度以保護使用者隱私（UA Client Hints），建議新應用使用 navigator.userAgentData 替代字串解析。

💡 常見使用場景

  • 從 UA 串識別瀏覽器/系統/裝置型別。
  • 分析訪問日誌時識別裝置與瀏覽器分佈，據此決定需要相容哪些版本、是否可以放棄舊瀏覽器。
解析
`Mozilla/5.0 (Windows NT 10.0) AppleWebKit … Chrome/120 Safari/537` → OS=Windows 10, Browser=Chrome 120。

❓ 常見問題（FAQ）

UA 能偽造嗎？
能，UA 僅為客戶端自報，不可作身份依據。
為什麼識別結果不準？
因為 UA 字串本身就是各廠商拼接的混亂歷史產物：很多瀏覽器為相容性會偽裝成其他瀏覽器（如 Edge 的 UA 裡含 Chrome 與 Safari 標識），安卓平板與手機的 UA 也難以區分。因此 UA 只適合做粗粒度統計，精確判斷應用特性檢測（feature detection）。
