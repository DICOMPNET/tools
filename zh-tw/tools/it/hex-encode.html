🔤 Hex Encode

📐 工作原理與說明
把文本按 UTF-8 編碼為位元組序列，逐位元組轉 16 進位制並在前面補 0 到兩位（開啟大寫時轉大寫），用所選分隔符依次連線；開啟字首選項時逐位元組加 0x（如 0x48 0x69）；解碼先按完整位元組語法校驗（0x 只能位於位元組開頭），再規範化，按嚴格 UTF-8（fatal:true, ignoreBOM:true）解碼，非法位元組報錯並給出 Latin-1 對照與原始位元組
本編解碼工具基於對應編碼標準(RFC/規範)，純前端本地處理，資料不上傳。 工具名稱：十六進位制編解碼 - 免費編碼解碼工具，線上十六進位制編解碼，免費使用。

📖 演算法說明

Encode text to hexadecimal and decode hex strings back to text.

Paste hexdump / memory dumps directly: 0x prefixes (per byte or per line), whitespace and common separators are ignored; strict UTF-8 errors show a Latin-1 fallback.

💡 常見使用場景

  • 檢視網絡卡抓包、記憶體 dump、顏色值時常用十六進位制表示位元組。
  • 除錯時把字串轉成 Hex 便於比對底層位元組。
編碼 "AB"
輸入 `AB` → 輸出 `4142`（A=0x41、B=0x42）；解碼 `4142` → `AB`。

❓ 常見問題（FAQ）

Hex 與 UTF-8 什麼關係？
Hex 只是位元組的文本表示，一個漢字按 UTF-8 通常佔 3 位元組，會編成 6 位 Hex。
Hex 和 Base64 該怎麼選？
Hex 每個位元組用 2 個字元、體積翻倍，但天然可讀、便於人眼比對與定位偏移，適合除錯、抓包與記憶體 dump；Base64 每 3 位元組編成 4 字元、僅膨脹約 33%，適合傳輸與儲存。需要人看的用 Hex，需要省的用 Base64。
