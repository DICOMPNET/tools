📄 JSON Formatter

Syntax highlighting, tree view, sorting, escape/unescape, JSONP extraction. Pure frontend, no upload.

📐 工作原理與說明
對最近一次合法 JSON 遞迴統計各型別節點數：物件、陣列、字串、數字、布林、空值，以及總節點數、最大層級深度、物件鍵總數。柱狀圖按物件、陣列、字串、數字、布林、空值的固定順序展示節點數分佈（圖高 200）。明細表逐行輸出統計項與數值：總節點數、最大層級深度、物件鍵總數、值節點數（字串 + 數字 + 布林 + 空值之和）、序列化字元數（重新序列化後的字串長度），隨後再逐行輸出上述六類各自的節點數；表頭在英文態下替換為對應英文
將 JSON 文本解析為物件樹後重新序列化：美化按 2/4 空格縮排、保留層級；壓縮去除空白；校驗在解析失敗時定位錯誤行列。支援語法高亮與層級摺疊便於閱讀。
  • 合法 JSON 要求雙引號鍵、無尾逗號、無註釋（JSON5 才支援）。
  • 純前端解析，貼上內容不離開瀏覽器，適合脫敏前本地處理。

💡 常見使用場景

  • 美化 / 壓縮 JSON：把壓縮成單行的 JSON 按縮排展開便於閱讀，或反向壓縮以節省網路傳輸與日誌體積。JSON 語法規範見 RFC 8259（https://datatracker.ietf.org/doc/html/rfc8259）。
  • 定位語法錯誤：解析失敗時本工具會標出錯誤所在的行與列，快速定位缺引號、尾逗號、註釋等非法的位置。
  • 本地脫敏前處理：貼上含敏感欄位的 JSON，在瀏覽器內格式化 / 抽取，內容不上傳，適合在提交到協作工具前先理清結構。
格式化與壓縮
輸入 {"name":"John","age":30,"tags":["a","b"]} 點選美化後按 2 空格縮排展開為多行；點選壓縮則去除所有空白回到單行。僅調整空白，鍵值與順序不變。
校驗報錯定位
輸入 {"a":1,}，末尾多了一個逗號（非法尾逗號），解析失敗並提示錯誤行列（如第 1 行第 8 列附近），據此刪除多餘逗號即可通過。標準 JSON 不允許尾逗號與註釋。

❓ 常見問題（FAQ）

格式化會改變資料嗎？
不會。格式化只增刪空白與調整縮排，鍵值、陣列順序、資料型別全部保持不變；壓縮是格式化的逆操作。
為什麼解析失敗會報出行列？
JSON 解析器在遇錯時記錄已消費的字元位置，可換算成行號與列號。常見錯誤：鍵或字串用了單引號、鍵名無雙引號、存在尾逗號、混入了 // 或 /* 註釋（標準 JSON 不支援，JSON5 才支援）。
大檔案會變慢嗎？
純前端解析對幾 MB 的 JSON 一般仍可接受；若檔案極大（數十 MB），建議先用日誌 / 編輯器的區域性片段排查，避免一次性貼上卡頓。
