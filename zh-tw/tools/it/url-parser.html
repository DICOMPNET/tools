🔗 URLParser

📐 工作原理與說明
用 new URL(輸入) 解析，取出 href、protocol、hostname、port、host、pathname、search、hash、origin、username、password 等欄位，並用 searchParams.forEach 把查詢串展開為引數名到值的對映。欄位為空時顯示「(空)」，參數列逐行渲染為可複製的鍵值行；輸入為空時提示輸入 URL，構造失敗時給出錯誤提示
拆解 URL 的各個組成部分。
  • 結構：scheme://host:port/path?query#fragment。
  • 組成：協議、主機名、埠、路徑、查詢串與片段標識。
  • 埠：可省略，按協議取預設值（http 為 80、https 為 443）。
  • 用途：提取域名與路徑、校驗 URL 合法性、分析連結結構。

Parse any URL into scheme, host, path, query and fragment in your browser, and inspect or edit each component.

📋 URL結構說明

protocol://username:password@hostname:port/pathname?search#hash

部分說明示例
protocol協議，訪問資源的方式https:, http:, ftp:
hostname主機名/域名www.example.com
port埠號（可選）8080, 443
pathname路徑，資源位置/path/to/page
search查詢字串，?開頭?key=value&foo=bar
hash片段識別符號，#開頭#section
username/password認證資訊（少用）user:pass@

💡 常見使用場景

  • 拆出協議、主機、路徑、查詢、錨點。
  • 核對重定向規則：把 URL 拆開看清協議、主機、埠、路徑與查詢，確認規則匹配的是哪一部分。
解析
`https://ex.com:443/p?a=1&b=2#top` → protocol=https, host=ex.com, port=443, path=/p, query=a=1&b=2, hash=top。

❓ 常見問題（FAQ）

預設埠要顯示嗎？
解析會保留顯式埠；預設埠(80/443)常省略。
為什麼解析不出查詢引數？
常見原因：查詢串裡有未編碼的 #（會被當作片段識別符號，其後內容不屬於查詢）、多個 ? 導致切分錯誤，或引數值裡含 & 卻未編碼。另外相對 URL 需先基於一個基準 URL 解析，直接解析會缺少協議與主機部分。
⚠️ 使用說明與注意事項
  • 本工具純前端執行，資料不會上傳到伺服器
  • 建議在主流瀏覽器（Chrome/Safari/Firefox/Edge）中使用
  • 計算結果僅供參考，請以實際應用場景為準
