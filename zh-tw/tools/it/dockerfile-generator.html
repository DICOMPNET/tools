🖥️ Dockerfile Generator

Dockerfile Generator - Choose base image, exposed port and start command to produce a usable Dockerfile. Free, browser-only.

📐 工作原理與說明
基礎映象取輸入值（為空時用預設映象），埠取輸入值向下取整（為空時用 3000），啟動命令取輸入值（為空時用預設命令）並去掉其中的雙引號。按固定順序拼裝 Dockerfile：指定基礎映象、設定工作目錄、複製當前目錄內容、安裝生產環境依賴、宣告暴露埠、以陣列形式宣告啟動命令。輸出時對整段內容做 HTML 轉義後在程式碼塊中展示
按所選技術棧生成 Dockerfile 骨架與最佳實踐配置。
  • 指令：FROM 指定基礎映象、RUN 執行命令、COPY/ADD 複製檔案、WORKDIR 設工作目錄、ENV 設環境變數、EXPOSE 宣告埠、CMD/ENTRYPOINT 定義啟動命令。
  • 分層：每條指令生成一層；合併 RUN 可減少層數，把變動少的步驟前置以複用構建快取。
  • 瘦身：用多階段構建（multi-stage）只把產物拷入最終映象，並用 .dockerignore 排除無關檔案。
  • 安全：建議使用非 root 使用者執行，固定基礎映象版本標籤而非 latest。

⚠️ 使用說明與注意事項
  • 示例為單階段構建；生產建議用多階段構建（builder 階段編譯、runtime 階段只拷產物）以減小映象。
  • EXPOSE 僅宣告文件化埠，真正對映由 docker run -p 決定；二者應一致。
  • COPY . /app 前應放 .dockerignore 排除 node_modules 等，避免上下文臃腫與快取失效。

📋 多階段示例片段

FROM node:20 AS build
WORKDIR /app
COPY . .
RUN npm ci && npm run build
FROM node:20-alpine
COPY --from=build /app/dist /app
CMD ["npm","start"]

❓ 常見問題（FAQ）

多階段構建？
可生成 builder + runtime 兩階段瘦身。
為什麼映象這麼大？
常見原因有三：基礎映象選了完整版（如 ubuntu 而非 alpine/slim）、構建依賴沒刪（apt 快取、原始碼包）、構建產物與執行時混在同一層。用多階段構建只把執行所需檔案拷進最終映象，並把 apt-get clean 與刪除列表放在同一條 RUN 指令裡。
