🔐 Hash ID Generator

📐 工作原理與說明
輸入按逗號或空白切分後逐項轉整數並過濾非數字，無有效數字時提示；用 hashids 以鹽值、最小長度與自定義字母表（預設大小寫字母加數字共 62 字元）對數字陣列編碼，輸出 HashID 與原始輸入陣列
把數字 ID 編碼為短字串，隱藏自增 ID 規律。
  • 原理：對數字做混淆後按 Base62/Base58 等字母表編碼，得到短且無規律的串。
  • 可逆：使用相同鹽值可解碼回原始數字；換鹽則結果完全不同。
  • 注意：這屬於混淆（obfuscation）而非加密，不能作為訪問控制手段。
  • 用途：URL 中的短 ID、避免暴露業務量與列舉攻擊。

💡 常見使用場景

  • 把數字 ID 編碼成不易猜的短串（如 ?id=laHqu）。
  • 對外隱藏自增 ID：把資料庫主鍵 123 編碼成 xoz 之類的短串放在 URL 裡，避免暴露業務量與被遍歷爬取。
編碼
salt="my" 編碼 [1,2,3] → 如 `o2fXhV`（解碼回 [1,2,3]）。

❓ 常見問題（FAQ）

Hashids 可逆嗎？
可逆，是編碼非加密；換 salt 結果不同。
Hashids 能當安全措施嗎？
不能。它只是可逆的混淆編碼，拿到 salt 或足夠多的樣本就能反推，設計目標是「讓 ID 不好看」而非「讓 ID 不可猜」。若需要真正防遍歷，應使用不可預測且服務端可校驗的標識（如隨機 UUID）配合授權檢查——授權才是安全的邊界。
