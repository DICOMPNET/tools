🔄 Line Ending Converter

📐 工作原理與說明
先統計原文中三種換行的數量：回車換行、單獨回車（回車後不緊跟換行）、單獨換行（換行前不是回車），總換行數為三者之和；總數為 0 時提示文本中未檢測到換行符。隨後把文本中所有換行統一替換為目標換行符。展示三種換行的數量與總換行數，並給出主換行符判定、文本行數（總換行數不為 0 時取總換行數加 1，否則為 1）、字元數與 UTF-8 位元組數
在 LF、CRLF、CR 三種換行符之間轉換。
  • 三種行尾：LF（\n，Unix/macOS）、CRLF（\r\n，Windows）、CR（\r，舊 Mac）。
  • 轉換：統一替換行結束符；需避免誤替換文本中表示換行的字面 \n 字串。
  • 統一策略：Git 可用 core.autocrlf 或 .gitattributes 規範行尾。
  • 問題：混用行尾會造成 diff 噪音，並讓 shell 指令碼報 ^M 錯誤。

Convert line endings between CRLF and LF, and see how many lines each file style affects.

💡 常見使用場景

  • CRLF/LF/CR 互轉。
  • 跨平臺協作時統一換行：Windows 編輯器與 Linux 構建指令碼混用會導致 shell 指令碼報 ^M 錯誤，轉換後即可正常執行。
轉換
Windows CRLF `\r\n` → Unix LF `\n`。

❓ 常見問題（FAQ）

為何要統一？
跨平臺指令碼/校驗常因換行不一致報錯。
Git 能自動處理換行嗎？
可以。core.autocrlf=true 在檢出時轉 CRLF、提交時轉 LF（適合 Windows）；Linux/macOS 應設為 input（提交時轉 LF，檢出不變）。更可靠的做法是在倉庫里加 .gitattributes（如 * text=auto）統一約定，避免依賴每個人的本地配置。
