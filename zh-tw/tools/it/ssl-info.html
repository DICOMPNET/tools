🔐 Ssl Info

Decode and inspect SSL/TLS certificate details (issuer, validity, SAN) from a host in your browser.

📐 工作原理與說明
金鑰空間 = 2^等效位數；平均嘗試次數 = 金鑰空間 ÷ 2；破解耗時 = 平均嘗試次數 ÷ 每秒嘗試速率（秒）；分級：超過 1e18 秒為極度安全、超過 1e15 秒為安全、超過 1e12 秒為邊緣、超過 1e9 秒為弱，否則不安全；等效安全位數：AES-128 = 128、AES-256 = 256、RSA-2048 = 112、RSA-4096 = 152、ECC-256 = 128、ECC-384 = 192、SHA-256 碰撞 = 128
SSL/TLS 與證書機制速查。
  • 握手：客戶端問候 → 服務端下發證書 → 金鑰交換 → 生成會話金鑰 → 對稱加密通訊。
  • 證書：包含域名、頒發者、有效期與公鑰，由上級 CA 簽名形成信任鏈。
  • 版本：TLS 1.2 與 1.3 為當前主流，TLS 1.3 將握手精簡到 1-RTT 並移除不安全演算法。
  • 校驗項：是否過期、域名是否匹配、信任鏈是否完整、是否已被吊銷（CRL/OCSP）。

TLS 各版本特性

版本釋出狀態關鍵特性
SSL 3.01996已廢棄POODLE 攻擊漏洞，2015 年起全面停用
TLS 1.01999已廢棄SSL 3.0 的標準化版本，2020 年起主流瀏覽器停用
TLS 1.12006已廢棄修復 CBC 顯式 IV，2020 年起主流瀏覽器停用
TLS 1.22008主流支援 AEAD（GCM/CCM）、SHA-256、橢圓曲線密碼（ECDHE）
TLS 1.32018推薦1-RTT 握手、強制 PFS、移除不安全演算法、0-RTT 恢復
建議：僅啟用 TLS 1.2 和 TLS 1.3。TLS 1.3 強制前向保密（PFS），並移除了 RSA 金鑰交換、靜態 DH、CBC 模式、RC4、MD5、SHA-1 等。

常見加密套件說明

套件命名格式：TLS_密钥交换_认证_加密_消息认证（TLS 1.3 簡化為 TLS_加密_消息认证）

TLS_AES_256_GCM_SHA384 TLS 1.3
AES-256-GCM 加密 + SHA-384 訊息認證，TLS 1.3 強制套件之一，安全性極高
TLS_CHACHA20_POLY1305_SHA256 TLS 1.3
ChaCha20-Poly1305，移動裝置效能優秀，無硬體加速時優於 AES-GCM
TLS_AES_128_GCM_SHA256 TLS 1.3
AES-128-GCM，效能與安全性平衡之選
ECDHE-RSA-AES256-GCM-SHA384 TLS 1.2
ECDHE 金鑰交換（PFS）+ RSA 認證 + AES-256-GCM，TLS 1.2 推薦配置
ECDHE-ECDSA-AES128-GCM-SHA256 TLS 1.2
ECDSA 證書（更小、更快）+ AES-128-GCM
AES128-SHA 停用
無 PFS、CBC 模式、SHA-1，存在 BEAST/Lucky13 攻擊風險
RC4-MD5 停用
RC4 流密碼已被破解，2015 年起全面停用
ECDHE-RSA-AES256-SHA384 不推薦
PFS 但使用 CBC 模式，存在 Lucky13 時序攻擊風險，建議改用 GCM

❓ 常見問題（FAQ）

證書鏈是什麼？
伺服器證+中間 CA+根 CA 逐級信任。
為什麼瀏覽器說證書無效？
常見原因有五：證書已過期、域名與 SAN 不匹配、中間證書缺失導致鏈不完整、系統時間錯誤、證書已被吊銷（需 OCSP/CRL 校驗）。另外自簽名證書不會被公開信任。按這個順序逐項確認，多數問題都能定位。
