📐 工作原理與說明
先做詞法切分：依次識別單行註釋 //、塊註釋 /* */、字串（含模板串中 ${} 的花括號配對）、正則（依上一個有意義 token 判斷 / 是除號還是正則起始：識別符號或數字後通常為除法，return/typeof/in/of/instanceof/new/delete/void/case/throw/else/do/yield/await 等關鍵字及運算子後為正則）、數字（含十六進位制與科學計數法，+/− 僅在 e/E 後併入）、識別符號與關鍵字。壓縮規則：刪註釋時單行註釋保留一個換行避免並行；摺疊空白時先把連續空白壓成空格，再去掉分號與運算子兩側的空白，並保留關鍵字與其後識別符號之間的必要空格；布林簡化 true → !0、false → !1；數字簡化去掉前導 0（0.5 → .5）。壓縮率 = (1 − 輸出長度 ÷ 輸入長度) × 100%，輸入長度為 0 時取 0
壓縮 JavaScript 體積以便更快傳輸。
  • 手段：刪除空白與註釋、縮短區域性變數名、合併語句、常量摺疊、去除死程式碼。
  • 前提：變換必須語義等價，需基於 AST 分析作用域後再改名。
  • 風險：依賴 Function.prototype.toString 或 eval 的程式碼可能被破壞。
  • 配套：應產出 source map，便於線上問題定位到原始碼。

❓ 常見問題（FAQ）

壓縮與混淆區別？
壓縮只去空白，混淆還改變數名。
壓縮後報錯怎麼定位？
靠 source map。構建時生成 .map 並在產物末尾保留 //# sourceMappingURL 註釋，瀏覽器與錯誤監控平臺就能還原到原始檔名與行號。注意不要把 map 檔案公開部署給所有人，否則原始碼等於公開。
