🔐 AES Encrypt Decrypt

Encrypt and decrypt text with AES-256 using a passphrase, all client-side. Keys are derived in your browser; nothing is sent anywhere.

📐 工作原理與說明
AES 分組 16 位元組。金鑰擴充套件：Nk = 金鑰位數 ÷ 32，輪數 Nr = Nk + 6，每輪 w[i] = w[i−Nk] ⊕ temp；i % Nk = 0 時 temp 先位元組迴圈左移一位、過 S 盒、再異或 RCON[i/Nk]，Nk > 6 且 i % Nk = 4 時 temp 逐位元組過 S 盒。輪函式：SubBytes 逐位元組過 S 盒；ShiftRows 第 1/2/3 行分別迴圈左移 1/2/3 位元組；MixColumns 中 xtime(x) = ((x << 1) ^ (((x >>> 7) & 1) × 0x1b)) & 0xff；AddRoundKey 逐位元組異或輪金鑰。填充用 PKCS#7（填充值 = 填充長度）；ECB 逐塊獨立加密；CBC 每塊先與上一密文塊異或；CFB / OFB / CTR 為流模式，CFB 與 OFB 的解密即再執行一次同一加密流程
AES 是對稱分組密碼：金鑰 128/192/256 位，分組固定 16 位元組。常見模式：ECB（同明文同密文，不推薦）、CBC（需隨機 IV、PKCS7 填充）、GCM（帶認證與完整性校驗，無需填充）。本工具經瀏覽器 Web Crypto API 在本地完成，金鑰不經網路。
  • 口令到金鑰通常用 PBKDF2/scrypt 派生並加鹽，避免弱口令直用。
  • GCM 的 IV 須唯一，密文含認證標籤防篡改。
  • 本地加解密僅供您自己資料，金鑰請妥善儲存（遺失不可恢復）。

📖 使用說明與安全建議

AES 演算法簡介：高階加密標準（AES）是一種對稱加密演算法，支援 128/192/256 位金鑰。

模式說明：

• ECB：電子密碼本，最簡單但不安全，相同明文塊產生相同密文

• CBC：密碼分組連結，推薦使用，每個明文塊與前一個密文塊異或

• CFB：密碼反饋，將分組密碼轉換為流密碼

• OFB：輸出反饋，將分組密碼轉換為流密碼，誤差不傳播

• CTR：計數器模式，使用計數器生成金鑰流，可並行處理

安全建議：

• 推薦使用 AES-256 + CBC 或 CTR 模式

• 始終使用隨機生成的 IV，IV 不需要保密但必須唯一

• 使用 Salt 加鹽防止彩虹表攻擊

• 密碼應足夠複雜（至少12位，包含大小寫、數字、符號）

• ECB 模式不推薦用於加密大於一個塊的資料

• 本工具在瀏覽器本地執行，資料不會上傳到伺服器

PBKDF2 金鑰派生：使用 SHA-256 雜湊，100000 次迭代從密碼派生金鑰。

📚 深度解析：AES 加密 / 解密

💡 常見使用場景

  • 用 AES-256（CBC/GCM）對敏感配置、日誌做對稱加密。
  • 配置檔案脫敏：把資料庫密碼、第三方金鑰等敏感項用 AES-GCM 加密後寫進配置倉庫，部署時再用同一金鑰解出，避免明文入庫。
流程示意
明文 + 金鑰(32位元組) + 隨機 IV → 密文；GCM 模式額外產出認證標籤防篡改。解密需相同金鑰與 IV。

❓ 常見問題（FAQ）

CBC 與 GCM 怎麼選？
GCM 提供完整性校驗且並行友好，優先；CBC 需額外 HMAC 才安全。
把密文發給別人，對方怎麼解開？
AES 是對稱加密，雙方必須持有同一把金鑰。金鑰不能隨密文一起傳送——通常用非對稱演算法（如 RSA/ECDH）協商出會話金鑰，或用對方公鑰加密這把對稱金鑰後再傳輸。切勿把金鑰硬編碼進前端程式碼。
