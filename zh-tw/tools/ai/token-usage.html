🔑 Token Usage Estimator

Estimate token usage by the mix of Chinese, English and code in your text, and see how much tokenizers disagree.

📐 計算公式 / 原理
Token 估算（統一「每 token 字元數」口徑）：tokens=中文字數÷1.5+英文詞數×1.25+程式碼 tokens（中文≈1.5 字元/token；英文≈4 字元/token、平均 5 字元/詞即 1.25 token/詞；程式碼按輸入值直接計入）。校驗：無強校驗，空值按 0 兜底。判據：無固定分級，混合文本按三項加總。
混合內容按三類分別折算：中文按字元（1.5 字元/token）、英文按詞（約 1.25 token/詞）、程式碼按已計 token 數。與「Token 數量估算」頁同一口徑，費用換算見「提示詞 Token 成本」頁。這是粗略預算工具，實際值隨分詞器與符號密度浮動 ±20%，判斷是否接近上下文上限時應留安全餘量。

📐 計算公式與說明

口徑判讀（與上式互補）：中文≈字數÷1.5（1.5 字元/token）、英文≈詞數×1.25（約 4 字元/token、5 字元/詞）為 BPE 經驗折算率，程式碼片段須按實際 token 數輸入；估算結果四捨五入取整展示。校驗：與上方一致，空值按 0 兜底。判據：無固定分級，三頁（token / token-usage / token-2）統一使用本口徑。

不同分詞器差異較大，僅供參考。

📚 深度解析：Token 用量估算

💡 常見使用場景

  • 按中英文與程式碼比例估算文本 token 數，提示不同分詞器差異。
  • 中文約 1~2 字/token(因模型而異)，英文約 4 字元/token，程式碼密度更高。
  • 估算用於把控上下文視窗與 API 成本，精確值需對應模型分詞器計數。
中英混排估算
一段 500 中文字+200 英文詞：中文≈500÷1.5=333 token，英文≈200÷0.75=267 token，合計≈600 token；程式碼部分按已計數的 token 直接相加。實際因模型分詞不同會有偏差。

❓ 常見問題（FAQ）

為什麼中文 token 數不固定？
不同模型對中文的子詞切分不同(按字/按詞/混合)，同一段中文 token 數可差數倍；本估算僅給量級，精確需對應分詞器。
程式碼為什麼更費 token？
程式碼含大量符號、縮排與識別符號，資訊密度高、子詞切分更碎，同等字元數常比自然語言消耗更多 token。
