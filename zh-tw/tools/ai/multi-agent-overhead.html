🤖 Multi-Agent Communication Overhead Estimator

Estimate the communication overhead of a fully-connected multi-agent system from agent count and message frequency, before you commit to an architecture.

📐 計算公式 / 原理
多智慧體通訊開銷（本頁程式碼口徑）：訊息總數=智慧體數 n×(n−1)×輪數（全連線兩兩通道，每輪每對通道雙向各計 1 條）；總流量 KB=訊息總數×單條訊息大小 KB。校驗：無強校驗，空值按 0 兜底。判據：無固定分級，n 增大訊息總數按平方量級增長。
全連線廣播模式下每個智慧體每輪要向其餘 n−1 個發訊息，通訊量隨智慧體數量呈平方增長，這是多智慧體系統規模化的主要瓶頸。改為分層或共享黑板（blackboard）可把複雜度降到線性。

📐 計算公式與說明

判讀與延伸（與上方公式互補，共用同一組輸入）：兩兩通道數=n×(n−1)；每智慧體訊息=n×(n−1)×輪數÷n=(n−1)×輪數；增加 1 個智慧體後訊息總數變為原值的(n+1)×n÷(n×(n−1)) 倍，頁面按同口徑展示擴張倍率與歷史對照。校驗：與上方一致，空值按 0 兜底。判據：無固定分級，輪數與訊息規模線性正相關。

隨智慧體數平方增長，需謹慎設計拓撲。

📚 深度解析：多智慧體通訊開銷

💡 常見使用場景

  • 全連線拓撲下每輪訊息數=C(n,2)=n(n−1)/2，隨智慧體數平方增長。
  • 開銷=訊息數×單訊息體量(上下文/token)，是通訊瓶頸與成本主因。
  • 可用分層/星型/廣播拓撲削減邊數，或用摘要壓縮降低單訊息體量。
全連線開銷
n=10 個智慧體全連線：每輪訊息=10×9/2=45 條。若單條含 2k token，每輪通訊≈90k token；n=20 時訊息=190，開銷約 4 倍，增長極快。

❓ 常見問題（FAQ）

怎麼降低多智慧體通訊成本？
改全連線為星型/分層(中心協調)，減少邊數；訊息用摘要而非全文；並設定通訊輪次上限，避免無限對話空轉。
全連線有必要嗎？
多數任務不需要。全連線讓任意兩體直連、資訊同步快但成本高；若任務可分解，子團隊+彙總更高效，價效比更好。
