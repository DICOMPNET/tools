📚 Context Window Usage Calculator

Count the tokens in your prompt and expected completion and see how much of the model context window they consume.

📐 計算公式 / 原理
佔用率 = (系統提示 + 使用者輸入 + 預期回覆) / 上下文視窗 × 100%；剩餘 = 視窗 − 已用
規劃對話時把預期回覆長度一併計入，避免生成到一半撞上視窗上限被截斷。長視窗模型雖標稱很大，但注意力成本隨長度平方增長，且中段內容容易被忽略（lost-in-the-middle），並非越長越好。

📐 計算公式與說明

上下文佔用構成與超限判定（與佔用率式互補）：已用=系統提示+使用者輸入+回覆預留（token）；儀表盤與佔比僅在視窗上限>0 時繪製，分母為 0 顯示 ⚠ 提示。校驗：無強校驗，空值按 0 兜底。判據：超限判定 已用>視窗上限 → 已超限（YES），否則未超（no）；佔用越低，留給長輸出與多輪對話的餘量越大。

超出上限需截斷或摘要歷史。

📚 深度解析：上下文窗口占用

💡 常見使用場景

  • 佔用比=提示詞 token + 生成 token / 視窗上限(如 4k/32k/128k)。
  • 中英混排時中文按字或 subword 計，需以具體分詞器為準估算。
  • 佔用超 100% 將截斷，長任務應預留生成空間並定期壓縮歷史。
佔用預警
視窗 8k，提示 6k + 預計生成 2k = 8k 恰好滿；若實際生成超 2k 即溢位。建議提示控制在 5k 以內留 3k 給生成。

❓ 常見問題（FAQ）

為什麼顯示佔用滿了卻還能聊？
部分實現會滾動丟棄最早歷史以維持視窗，表現為'能繼續但忘了開頭'；嚴格實現則直接報錯。佔用比應預留生成餘量。
不同模型 token 數一樣嗎？
不同。同一段中文在 GPT/Claude/國產模型下 token 數差異明顯，估算僅供參考，精確值需對應分詞器計數。
