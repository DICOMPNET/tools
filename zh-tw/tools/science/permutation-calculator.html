🔀 Permutations Calculator P(n,r)

📐 工作原理與說明
排列數（本頁程式碼口徑，BigInt 精確計算）：P(n,r)=n×(n−1)×…×(n−r+1)（從 n 連乘到 n−r+1，避免先算大數階乘再相除的溢位），千分位展示精確值。校驗：n、r 須為整數（非整數提示「請輸入整數」），且均非負、r≤n，否則分別提示並中止。判據：無固定分級，r=0 結果為 1，n=r 即全排列 n!；r≤20 時頁面展開連乘步驟。
排列數 P(n,r)=n!/(n−r)!=n×(n−1)×…×(n−r+1)，計順序；本頁用 BigInt 精確連乘，要求 n、r 為非負整數且 r≤n，r≤20 時展開連乘步驟。

Compute the number of ordered arrangements of r items from n with P(n,r) = n! / (n−r)!.

從 n 個不同元素中取 r 個的排列數：P(n,r) = n! / (n−r)!

📚 深度解析：排列數 P(n, r)

💡 常見使用場景

  • 從 n 取 r 計順序。
  • 密碼位數與賽程排序等計較順序的計數問題。
計算
P(10,3)=10·9·8=720。
📖 定義與公式
從 n 個不同元素中有序地選取 r 個，方案數為排列數 P(n,r)=n!/(n−r)!=n×(n−1)×…×(n−r+1)。邊界：P(n,0)=1（空排列唯一）、P(n,n)=n!（全排列）、P(n,1)=n。與組合數的關係：C(n,r)=P(n,r)/r!，組合不計順序，排列計順序。本頁用 BigInt 連乘避免先算階乘再相除的溢位，r≤20 時展開連乘步驟，結果按千分位顯示。
⚠️ 適用條件與常見誤用
r 不能大於 n；n、r 必須是非負整數，頁面分別提示「請輸入整數」「r 不能大於 n」。 誤用一：把排列與組合混用——只要交換選取順序算不同方案就用 P，否則用 C。 誤用二：元素有重複時不能直接用 P(n,r)，應按 n!/(n₁!·n₂!·…) 去重。 n 很大時結果超出日常可讀範圍，頁面雖用 BigInt 精確，仍建議只作計數參考。 r≤20 才展開連乘步驟，更大 r 只給結果，避免頁面輸出過長。
📊 多組輸入對照（實跑）
n=10, r=3：10×9×8 = 720，步驟行展開 10! / 7! 的約分過程。 n=7, r=4：7×6×5×4 = 840，與 7! / 3! 一致；同參數組合數 C(7,4) = 840 / 24 = 35，可用來交叉驗證。 n=8, r=2：8×7 = 56；改為不計順序的組合則是 C(8,2) = 28，正好是 56 / 2!。 n=5, r=0：結果為 1，頁面額外說明「r=0：只有 1 種方案（不取任何元素）」。 n=5, r=6：頁面提示「r 不能大於 n」，不輸出數值。
🧭 使用場景與取值建議
判斷用 P 還是 C 只需問一句「交換順序算不算不同方案」：10 人跑出前三名（金/銀/銅）是 P(10,3) = 720；從 10 人裡選 3 人組成小組則是 C(10,3) = 120。其他常見場景：4 位不重複數字的密碼共 P(10,4) = 5,040 種；8 人排成一排是 P(8,8) = 40,320 種。頁面用 BigInt 連乘，避免先算 n! 再相除造成的溢位，但 n 很大時結果本身已超出日常可讀範圍。
P(10, 3)
10×9×8=720：從 10 個裡選 3 個並排序（如前三名領獎臺），共 720 種。
P(7, 4)
7×6×5×4=840；頁面同時展開 7! / 3! 的約分過程，與連乘結果一致。
P(8, 2) 與 P(n, 0)
P(8,2)=8×7=56；P(n,0)=1。若把同樣的 8 選 2 改成不計順序的組合，則為 C(8,2)=28，正好是排列數的一半（2!）。

❓ 常見問題（FAQ）

與組合關係？
P(n,r)=C(n,r)·r!。
有重複元素怎麼算？
總數除以各重複元素個數的階乘。
P(n,r) 為什麼等於 n!/(n−r)!？
第 1 位有 n 種、第 2 位 n−1 種……第 r 位 n−r+1 種，連乘即 n×(n−1)×…×(n−r+1)，恰好是 n! 與 (n−r)! 的商。
什麼時候用排列而不是組合？
順序有意義時用排列（密碼、賽程名次、排隊），順序無意義時用組合（選人組隊、抽獎中獎組合）。
為什麼 P(n,0) 等於 1 而不是 0？
「不取任何元素」只有一種方式（空排列），這是計數里的空積約定，和 0! = 1 同源；同理 P(n,n) = n! 表示全排列。
結果很大時頁面還準嗎？
頁面用 BigInt 連乘，整數結果精確；但位數過多時人眼難以核對，建議同時用對數估算量級（log₁₀P ≈ Σlog₁₀i）。
