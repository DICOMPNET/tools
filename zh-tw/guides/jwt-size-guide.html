JWT 長度估算使用指南

按 header、payload 與簽名的位元組數估算 JWT 編碼後的字串長度，便於控制請求頭與 URL 體積。按 header/payload/signature 大小估算編碼後 JWT 總長度。

計算公式與原理

JWT = base64url(header) + . + base64url(payload) + . + base64url(signature)

JWT 由 base64url(header)、base64url(payload)、base64url(signature) 三段以點號連線，總長度為三段編碼後字元數之和再加 2 個分隔符；base64url 每 3 位元組編碼為 4 字元且不補 = 填充。

典型使用場景

  • 按 header/payload/signature 大小估算編碼後 JWT 總長度。
  • 評估會話令牌對請求頭體積的影響。
  • 判斷是否需要用緊湊宣告減少長度。

算例參考

  • 精簡宣告：header+payload 各 120 位元組、簽名 32 位元組，Base64 膨脹約 33% 後令牌約 250 位元組，適合放入 Cookie。
  • 宣告過多導致超長：payload 達 1 KB 時令牌可超 1.4 KB，可能觸及閘道器頭部上限，應裁剪非必要宣告。

注意事項

本工具純前端執行，輸入內容不上傳伺服器；結果為按上述口徑得到的理論估算值。實際應用受裝置引數、測量條件與當地規範影響，請以裝置銘牌、檢測報告與現行標準為準，重大決策建議諮詢專業人士。

JWT 為什麼會變長？
三段均由 Base64URL 編碼，原始 JSON 體積會膨脹約 33%，簽名段再疊加固定長度。
多長算安全？
安全性與長度無直接關係，但過長會佔用請求頭配額，建議僅放必要宣告。
