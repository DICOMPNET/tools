YAML 與 JSON 的關係

YAML 是 JSON 的超集，用縮排表達層級、更易讀，常用於配置檔案（如 CI、K8s）。它本質仍可轉為 JSON，因此「先當 JSON 校驗」是常見排錯思路。

最常見的錯誤：縮排

YAML 對空格縮排極其敏感，Tab 與空格混用會直接報錯。統一用 2 個空格，且同層必須對齊。

在 ToolBox 中校驗/轉換

貼上 YAML 點選校驗，錯誤會定位到行；一鍵轉為 JSON 後可直接用 JSON 工具鏈繼續處理。

常見問題

YAML 的 & 錨點和 * 別名是什麼？
它們是 YAML 的複用機制：&anchor 定義、*alias 引用，能減少重複；轉換 JSON 時會被展開為實際值。
布林值 true/false 會被誤轉嗎？
會。YAML 把 yes/no/on/off 也當布林，敏感場景下建議加引號寫成 "yes" 以避免歧義。
Tab 真的不能用嗎？
標準 YAML 不允許 Tab 縮排，很多解析器會直接報錯；務必用空格。
