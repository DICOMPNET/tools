參觀流線規劃 使用指南

以展廳為節點、通道距離為邊權，用 Dijkstra 演算法規劃入口到出口的最短參觀流線，並支援按順序串聯必看節點；空值、非數值與負距離會被排除並提示，不會靜默當成 0。

功能說明

頁面把當前展廳列表建成無向圖，每條通道的距離作為非負權重。起點、必看節點與終點按輸入順序分段求最短路徑後拼接，總距離為各段之和。端點已失效的通道、距離為空或為負數的通道都不會進入圖，並在結果上方列出原因；這樣未知通道不會因為權重 0 而被誤選為最短路徑。

典型使用場景

  • 設計常設展動線：入口→青銅館→陶瓷館→書畫館→玉器館→出口，比較不同串聯順序的總步行距離。
  • 限流時把某段通道距離調大，觀察路線是否繞開該區域。
  • 只去重點館時，把重點館填入“必看節點”，按順序分段計算。

操作步驟

  1. 確認展廳列表完整，修改名稱後舊通道端點會標紅。
  2. 逐條填寫通道兩端與距離（米）；已知同址通道可明確填 0，未知距離必須留待補測而不是填 0。
  3. 選擇起點、終點，必要時填寫逗號分隔的必看節點。
  4. 點選“規劃最短流線”，檢視路徑、分段距離與總距離；有無效通道時先按提示修正。

算例參考

  • A（入口）→B 20 m、B→C 30 m、A→C 直連 80 m：A→B→C 合計 50 m，短於直連 80 m。
  • 若 B→C 距離留空，該邊被排除；此時只能走 A→C 80 m，並在結果上方提示“距離為空”。
  • 若某條通道填 −10 m，該邊被拒絕，不再取絕對值 10 m 參與計算。

注意事項

Dijkstra 只適用於非負權重，因此負距離必須修正而不是取絕對值。距離為 0 只應出現在確實同址的通道；未知通道按 0 計算會製造一條“免費捷徑”。端點名稱含 HTML 字元時，頁面統一轉義後再顯示，不會改變提示結構。路線最佳化只看距離，不自動考慮客流、單向限流或無障礙條件。

通道距離留空會怎樣？
該通道被排除並在結果上方提示，不會當成 0 參與最短路徑；請補測或刪除該通道。
負距離為什麼不再自動取絕對值？
負權會破壞 Dijkstra 的前提，也可能造成前驅成環；工具直接拒絕並提示修正，避免給出錯誤路線。
為什麼有時繞路反而更短？
演算法按累計權重求全域性最短，直線近不代表總距離小；經中轉節點可能累計更少。
必看節點如何串聯？
按輸入順序逐段求最短再拼接，不會自動重排順序；如需最佳化順序，請調整輸入次序後比較總距離。

為什麼有時繞路反而更短？
Dijkstra 按邊的權重（通道距離）求全域性最短，並非直線近就快；經中轉節點可能累計權重更小（如 A→B→C=50m < 直連 80m）。規劃以演算法結果為準，憑直覺易誤判。
權重除了距離還能用什麼？
可把邊權設為通行時間、擁擠度或能耗，演算法同樣適用；若要考慮「必經重點館」，可設其為中間節點分段求解再拼接路徑，得到帶約束的最短動線。
